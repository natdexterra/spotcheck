## Rules (normative)

### Copy

- No em dash (U+2014) or en dash (U+2013) in any string the interface renders: log sentences, strip lines, summary lines, hints, captions, announcements, `aria-label`s. Separators follow the strip's convention: a middle dot with spaces (` · `) between fragments of one line, a colon before a code or a value, a full stop between two sentences. Examples: "Reviewed in 1:48 · from the agent's first write to confirm"; "Agent drafted it from the open gaps. Edit anything before sending"; "Agent proposal for Material was rejected: FIELD_LOCKED"; "You edited Quantity: agent 800 → yours 750"; "Agent proposed Delivery: All units within two weeks…". Document text from `data/` is rendered verbatim and is not touched.
- The `→` between an agent value and the person's value stays (it is the arrow icon's text form only inside log sentences and the summary; DESIGN.md's rule on arrows as icons applies to the interface chrome, not to a sentence).
- A unit test walks every string literal in `src/**/*.tsx` and `src/**/*.ts` (excluding tests and `data/`) and fails on U+2013 or U+2014; region text and fixture content are excluded by path.
- `DESIGN.md` § Copy grammar: the example "You edited Quantity — agent 800 → yours 750" becomes "You edited Quantity: agent 800 → yours 750".

### Editor

Per export 12, the editor **replaces the value line inside the row**; the row keeps its marker, label, lock glyph and badge, and hides its value, provenance links, rationale, "was:" line, agent-original line and the action row while the editor is open. Structure, top to bottom:

1. Label row as in the closed row (label + lock when locked, badge at the right).
2. A context line in `--ink-secondary`: unit-bearing field without a unit → "no unit given · the value cannot be verified until a unit is set"; plain field with an agent proposal → "Agent: {value} · {first source link}"; empty field → "no agent proposal · whatever you type here is yours alone".
3. Micro-labels `value` and, on `overall_dimensions`, `unit`, lowercase, `--text-sm`, `--ink-secondary`, on one line above the controls.
4. The input and, beside it, the segmented `in | mm` control: **both `--control-input` (42px) tall, tops aligned, bottoms aligned**; the input's focus ring is an outline with offset and does not change its box; the segmented control's border is the same `--border-input` hairline as the input. Gap between them `--space-2` (the inline-siblings role).
5. Validation line (icon + text in `--state-conflict`) when present, else the hint line per export 12: unit-bearing field "Locks on the first keystroke · after that no agent proposal can replace what you are typing"; plain field with an agent proposal "Locks on the first keystroke."; empty field: no hint line; after a clear on any field "The field is already locked · you typed and cleared it".
6. `Save` (primary, compact height — the local primary of an open editor, export 12; one line added to DESIGN.md § Interaction states) · `Cancel` (text) · the hint "Enter saves and verifies · Esc cancels" in `--ink-secondary`.

No duplicated field name inside the editor (the row's label is the editor's label). The editor's width is the row's content lane. Focus rules from P2 stand (first keystroke dispatches `edit_start` once; `Esc` returns focus to the row's primary action; `Save` verifies).

### Value slot of verified rows

The value slot shows the field's value, or "—" when the value is `null`; it never shows the resolution wording. `asked_customer` and `dismissed` rows therefore read "—" when they had no value (a conflict or missing row sent to the customer) and keep their value when they had one (export 11's asked-customer row shows "Black powder coat"). The wording stays in the badge: "Not required · 0:42 ago", "Awaiting customer · 0:42 ago".

### Choice controls

The checked state of a checkbox (covers list in the Clarification tab) and of a radio (reason picker, unit control) must read at a glance: the 16px box fills with `--accent-strong`, the check is the set's check icon at 12px in `--bg-raised` (white on the accent, ≥ 3:1), stroke as the icon set's; a radio's dot is 8px `--bg-raised` on the same fill. Unchecked: `--bg-raised` fill, `--border-input` hairline. Focus ring per DESIGN.md. Exports 07 (covers) and 12 (picker) govern the layout; if the export's check is lighter than this rule, the rule wins, because the live run showed the export's version as nearly invisible. Component tests assert the classes; the e2e screenshot of the Clarification tab with all four covers checked goes into the pull request at 1920 and 390.

### Verified group header

- "{N} more verified · {names} · Show" only while at least one other group is visible; when every field is verified the header reads "{N} verified · {names} · Show".
- The names run is one line: `min-width: 0`, `overflow: hidden`, `text-overflow: ellipsis`; the full list is visible in the expanded rows. The `Show` / `Hide` disclosure is a text button with the chevron icon from the set (DESIGN.md § Interaction states: a disclosure carries a chevron, never a text caret); it never wraps and never moves.

## Rules (normative)

### Copy

- No em dash (U+2014) or en dash (U+2013) in any app-authored interface string: log sentences, strip lines, summary lines, hints, captions, announcements, `aria-label`s. Document text and agent-authored text (rationale, notes, drafts) render verbatim and are not touched. Separators follow the strip's convention: a middle dot with spaces (` · `) between fragments of one line, a colon before a code or a value, a full stop between two sentences. Examples: "Reviewed in 1:48 · from the agent's first write to confirm"; "Agent drafted it from the open gaps. Edit anything before sending"; "Agent proposal for Material was rejected: FIELD_LOCKED"; "You edited Quantity: agent 800 → yours 750"; "Agent proposed Delivery: All units within two weeks…". Document text and agent-authored text from `data/` reach the screen as written.
- The `→` between an agent value and the person's value stays (it is the arrow icon's text form only inside log sentences and the summary; DESIGN.md's rule on arrows as icons applies to the interface chrome, not to a sentence).
- A unit test walks every string literal in `src/**/*.tsx` and `src/**/*.ts` (excluding tests and `data/`) and fails on U+2013 or U+2014; region text and fixture content are excluded by path.
- `DESIGN.md` § Copy grammar: the example "You edited Quantity — agent 800 → yours 750" becomes "You edited Quantity: agent 800 → yours 750".

### Editor

Per export 12, the editor **replaces the value line inside the row**; the row keeps its marker, label, lock glyph and badge, and hides its value, provenance links, rationale, "was:" line, agent-original line and the action row while the editor is open. Structure, top to bottom:

1. Label row as in the closed row (label + lock when locked, badge at the right).
2. A context line in `--ink-secondary`: unit-bearing field without a unit → "no unit given · the value cannot be verified until a unit is set"; plain field with an agent proposal → "Agent: {value} · {first source link}"; empty field → "no agent proposal · whatever you type here is yours alone".
3. Micro-labels `value` and, on `overall_dimensions`, `unit`, lowercase, `--text-sm`, `--ink-secondary`, on one line above the controls.
4. The input and, beside it, the segmented `in | mm` control: **both `--control-input` (42px) tall, tops aligned, bottoms aligned**; the input's focus ring is an outline with offset and does not change its box; the segmented control's border is the same `--border-input` hairline as the input. Gap between them `--space-2` (the inline-siblings role).
5. Validation line (icon + text in `--state-conflict`) when present, else the hint line per export 12: unit-bearing field "Locks on the first keystroke · after that no agent proposal can replace what you are typing"; plain field with an agent proposal "Locks on the first keystroke."; empty field: no hint line; after a clear on any field "The field is already locked · you typed and cleared it".
6. `Save` (primary, compact height — the local primary of an open editor, export 12; one line added to DESIGN.md § Interaction states) · `Cancel` (text) · the hint "Enter saves and verifies · Esc cancels" in `--ink-secondary`.

No duplicated field name inside the editor (the row's label is the editor's label). The editor's width is the row's content lane. Focus rules from P2 stand (first keystroke dispatches `edit_start` once; `Esc` returns focus to the row's primary action; `Save` verifies).

### Value slot of verified rows

The value slot shows the field's value, or "—" when the value is `null`; it never shows the resolution wording. `asked_customer` and `dismissed` rows therefore read "—" when they had no value (a conflict or missing row sent to the customer) and keep their value when they had one (export 11's asked-customer row shows "Black powder coat"). The wording stays in the badge: "Not required · 0:42 ago", "Awaiting customer · 0:42 ago".

### Choice controls

The checked state of a checkbox (covers list in the Clarification tab) and of a radio (reason picker, unit control) must read at a glance: the 16px box fills with `--accent-strong`, the check is the set's check icon at 12px in `--bg-raised` (white on the accent, ≥ 3:1), stroke as the icon set's; a radio's dot is 8px `--bg-raised` on the same fill. Unchecked: `--bg-raised` fill, `--border-input` hairline. Focus ring per DESIGN.md. Exports 07 (covers) and 12 (picker) govern the layout; if the export's check is lighter than this rule, the rule wins, because the live run showed the export's version as nearly invisible. Component tests assert the classes; the e2e screenshot of the Clarification tab with all four covers checked goes into the pull request at 1920 and 390.

### Verified group header

- "{N} more verified · {names} · Show" only while at least one other group is visible; when every field is verified the header reads "{N} verified · {names} · Show".
- The names run is one line: `min-width: 0`, `overflow: hidden`, `text-overflow: ellipsis`; the full list is visible in the expanded rows. The `Show` / `Hide` disclosure is a text button with the chevron icon from the set (DESIGN.md § Interaction states: a disclosure carries a chevron, never a text caret); it never wraps and never moves.

### Replay controls, simplified (owner's review of the P3 preview, 2026-09-02)

The replay serves B1 (a person without an agent watches the recorded session through the same state machine) and D14 (they may act while paused). It must let them watch at a human pace, stop to look, try an action, and start again; nothing else. These rules replace the P3 replay-row table:

| State | Row text at ≥ 1024px | Row text below 1024px | Controls |
|---|---|---|---|
| playing | `{label} · recorded {date} · step {n} of {total}` | `{short label} · {n} of {total}` | `Pause` (secondary compact) |
| paused | the playing text, then `next: {phrase}` on the same line | the short text; `next: {phrase}` on its own line under it | `Play` · `Next step` · `Restart` |
| ended | `{label} · finished · {total} steps` | `{short label} · finished` | `Restart` |
| error | `stopped at step {n}: {message}` (conflict color, icon) | same | `Restart` |

- `{label}` is "Sample session" or "Imported session"; `{short label}` is "Sample" or "Imported". `Next step` replaces `Next call` everywhere (a recorded step may be an estimator action). `Play`/`Pause` stay one button that keeps focus; `Restart` focuses `Play`.
- The "next:" phrase appears only while paused. The controls sit on the row text's line at 600px and above; below 600px the controls stack under the text and the fixed-slot rule does not apply. At 600px and above the control slot has a fixed width (the width of the three-button set) so a state change moves nothing. An e2e proves the controls beside the text block at 770, 820 and 1024 while playing and while paused (the paused text block may be two lines below 1024).
- `Export session` leaves the strip in every state (it stays in the expanded change-log header and in the confirm summary); the strip's export slot is removed.
- The strip's height is a minimum, not a fixed value: with the replay row present the strip grows and keeps its block padding, so the row never touches the bottom hairline (the P3 preview showed it sitting on the line at 1920).
- The quiet `live` line above and the `Play sample session` control in the expanded log during a live session are unchanged. Exports 15 and 16 are superseded where they differ; the pull request carries the four states at 1920, 820 and 390.

### Fidelity findings (state-by-state audit of production against exports 01–14, 2026-09-02)

Each line: what the export shows, the rule that applies, what to do. Rules over exports where they differ; where a rule and an export disagree the ruling is stated.

1. **Provenance links inside cards and under verified rows** inherit `lg`; exports 02/11 set them `sm` in every context. Rule: a provenance link is `--text-sm` mono wherever it appears (row, candidate card, suggestion card, verified row, editor context line).
2. **Document measure**: email/spec/clarification text runs the full pane (~110ch at 1920); exports 02/06/07 cap the column at 680px inside the pane. Rule: document text column `max-width: 680px` on the document lane; the tab row and the highlight follow the column.
3. **`Ask customer` on-state** carries a `--bg-subtle` pill; DESIGN.md § Interaction states: no pill on a state. Fix: icon + ink label, no fill. Add the consequence line under the actions from export 11: "Marked for the clarification email. This field still counts as open."
4. **`Pick`** on a `--bg-subtle` candidate card is the same colour as the card and 56px tall. Rule: the card is `--bg-raised` with a `--hairline` border (export 02); `Pick` is secondary compact (30px), not stretched.
5. **Missing rows** show no searched-document chips; P2 § Field pane requires "searched-document chips · the note · Enter value · Mark not required". Fix: chips from `searched`, `sm` mono, before the note.
6. **Verified rows** lack the resolution sentence of export 11: "the agent's value, kept as proposed · spec §2.1" (verified), "agent 800 → yours 750 · spec §1.1" (edited/picked/applied), "no agent proposal · you typed this one" (entered). Fix: one sentence per resolution kind, sans `md` secondary, provenance links inside it at `sm`.
7. **Empty rows** carry no explanation; export 11: "The agent has proposed nothing here. It may still be reading, or it skipped the field." Fix: the line in `--ink-secondary` under the value; first load keeps the eleven one-line rows of export 01 by rendering the line and the actions only after the first tool call (before it the row is label · — · badge).
8. **Collapsed change-log bar**: exports 01/02/16 show a fixed "Change log" label at the left and the entry count as the disclosure link at the right ("23 entries"); the shipped bar shows the sentence and "Show change log". Ruling: the export wins (the P3 task's "shipped label stays" is withdrawn): label · time · sentence (one line, ellipsis) · "{N} entries" disclosure with the chevron. Expanded header: "Change log" at `--text-lg` (not `xl`) with the meta line "{N} entries · agent and you" per export 16.
9. **Narrow change-log sheet header** (390): title clipped at the top, `Close` on a second line, no meta line; export 14. Fix: sheet padding-top `--space-4`, title and `Close` on one row, meta line under the title; long entries keep the time column.
10. **Third lane at 820**: header and strip sit on `--page-margin` while the 680px column is centred. Ruling for DESIGN.md's two rules: on one-column widths the lane is the column's left edge — header, strip and log bar content align to the centred column (export 04).
11. **"1 calls" / "0 calls"**: pluralise ("1 call", "0 calls"); same for "tools" and "entries".
12. **Clarification tab dot** renders after the label; exports 07/13 put it before. Fix the order.
13. **Provenance highlight** hugs the text; export 02 insets it by `--space-1` on each side. Fix.
14. **Strip prompt wraps at 390** — accepted by the owner on 2026-09-01 (quoted text, not a label); update P2's strip rule text to say so instead of "never broken"; no code change.
15. **Source pane after confirm**: export 08 hides it, P2 § Confirm says it "still works". Ruling: the export; update the P2 rule text; no code change.
16. **First-load blocker line** reads "Blocked by 11 not extracted"; P2 § Shell says "11 to check" for the first load while its blocker rule counts by state. Ruling: counts by state ("11 not extracted"); update the P2 first-load line; no code change.
17. Already covered elsewhere: mono size and drawing caption (P3), editor structure and heights (§ Editor above), header tagline removed by D18 (rule wins over exports 01–08).

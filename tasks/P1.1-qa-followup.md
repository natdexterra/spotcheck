# P1.1 — Core follow-up: dataset titles, replay coverage, persistence guard

**Status:** done — 2026-09-01
**PR:** [#3](https://github.com/natdexterra/spotcheck/pull/3)
**Depends on:** P1 (branches from main)

## Goal

Fix the confirmed review findings from PR #2 that sit outside P1's acceptance contract: the loader drops authored section titles over the real dataset, replay mishandles partially viewer-covered `send` steps and no-op viewer actions, starting a replay overwrites the saved live session, and agent inputs have no length caps. Pure core work — no UI, no new features.

## Scope — files to modify (regression test first for every fix; nothing else changes)

| Path | Fix |
|---|---|
| `src/data/package.ts` | preserve authored titles from `data/package.json` (`doc.title ?? fallback`, same for sections); titles stay app-authored, never lifted from document content |
| `src/replay/replay.ts` | partial-coverage `send`: drop only viewer-handled ids from `covers`, dispatch the reduced send, log the dropped subset; skip the whole step only when every covered field is viewer-handled (build-spec D14). Mark a field viewer-handled only when the viewer's action actually mutated it — log-only no-ops on fixture-locked fields must not poison the set. Route `createReplay` fixtures through `parseFixture` |
| `src/replay/persistence.ts` | suspend persistence while a replay owns the store (pause/resume); `createReplay`/`restart` must not overwrite the saved live session; persistence resumes when the replay releases the store |
| `src/state/agent-validation.ts` | length caps in `validateWrite`, rejected with the existing input-validation code and a message naming the member and its cap: `value` ≤ 400, `unit` ≤ 40, `rationale` ≤ 600, `note` ≤ 600, `subject` ≤ 200, `body` ≤ 4000, `source_refs` ≤ 12 refs of ≤ 64 chars, `candidates` ≤ 8. Stored `Proposal`/`Candidate`/`Suggestion` objects are key-picked — no extraneous input keys survive into state |

## Acceptance criteria

- [x] Each fix lands with a regression test that failed before it (TDD; commit per green step, subjects `P1.1 <area>: …`)
- [x] Over the real `data/package.json`, `list_rfq_documents` returns the authored titles (`s1` reads "Project Objective", not "Requirements")

- [x] A saved live session survives `createReplay()` and `restart()` byte-identical; persistence resumes after the replay ends
- [x] Every cap enforced and tested; the fixture result-size budget test stays green
- [x] All P1 tests untouched and green; `pnpm test` and `pnpm build` clean; no changes to `App.tsx`, `main.tsx`, styles, configs, `tasks/`, or `data/`
